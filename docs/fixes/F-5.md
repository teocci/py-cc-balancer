# F-5 — Switching accounts across venues silently corrupts P&L (global book shared across accounts)

- **Fix ID:** F-5
- **Version:** 0.2.0
- **Date:** 2026-07-17
- **Related work:** delivered by improvement [I-8](../improvements/I-8.md) (per-account data isolation + stable identity)
- **Status:** ✅ DONE (432 tests; live-verified).

## Symptom

All per-account state lives in a single global book under `~/.ccbalancer/`
(`portfolio.json`, `state.json`, `history.jsonl`, `ledger.jsonl`, `decision_log.jsonl`,
`flags.json`). Because the active-account (`--account`, formerly `--profile`) selector only
swaps **credentials + venue**, not the book, switching accounts and acting silently mixes data:

- `auth use <other> && rebalance` rebalances one account's target ratios against **another
  account's** live balances.
- `ledger.jsonl` interleaves fills from different exchange accounts, so `performance` /
  `performance --history` compute **cost basis and realized P&L across accounts** — silently wrong.
- `state.json` (last rebalance per pair) and `flags.json` (allocation/drift milestones) are
  likewise cross-contaminated.

No error is raised; the corruption is invisible until the numbers are questioned. Confirmed in
practice: two real accounts (`bybit` live, `okx` live) share one global book today.

## Root cause

Path resolution keys every data file on `config.app_dir / <FILE>` with **no account
dimension**. The auth layer models multiple accounts (`auth.json` + active pointer), but the
data layer was never scoped to match — a design gap from the Auth phase, which added
multi-account credentials without isolating the per-account book.

## Fix

Give each account its own data directory keyed by a **stable, immutable local id** (not the
mutable slug, not a creds hash — both would strand a book on rename / key rotation):

- New `AppConfig.data_dir = app_dir / 'accounts' / <account.id>` (or `accounts/default/` for
  the no-account env-credential path). The six book files route through `data_dir`; global /
  public files (`config.toml`, `indicators.toml`, `auth.json`, `.env`, `STOP`, `ohlcv/`) stay
  on `app_dir`.
- The `id` is minted once and preserved across `auth rename` and in-place credential rotation,
  so the book is never stranded. (The keyring stays keyed by account name; `auth rename` moves
  the keyring entry, while the id-keyed data dir is untouched.)
- A best-effort exchange `account_ref` (hashed exchange account id, captured online at login)
  **guards credential rotation**: a renewed key that resolves to a *different* exchange account
  is refused (`--force` overrides), so a rotated key cannot silently re-point the book.
- One-time guarded migration assigns existing root-level books to the active account (atomic
  `Path.replace`, idempotent). Prior cross-account mixing already in `ledger.jsonl` predates
  the fix and cannot be retroactively separated.

The identity/isolation machinery is improvement [I-8](../improvements/I-8.md); this fix row
records the correctness bug it closes. See I-8 for the full approach, files, and the
reattach-after-logout scope note.

## Files changed

See [I-8](../improvements/I-8.md#files-changed) — F-5 is closed by the same code change.
Correctness-critical files: `src/ccbalancer/config.py` (`data_dir` + `_migrate_legacy_book`),
`src/ccbalancer/cli.py` (six book stores routed through `config.data_dir`),
`src/ccbalancer/stores/auth_store.py` (stable `id`).

## Verification

- Two real accounts (bybit, okx) keep fully separate `portfolio/state/ledger/...`; a `pair add`
  under one is invisible to the other (live-verified; distinct `accounts/<id>/` dirs).
- `performance` / `performance --history` read only the active account's `ledger.jsonl`, so
  cost basis and P&L never mix across accounts.
- Legacy root books migrate once into the active account's dir (idempotent, no duplication);
  the env path lands in `accounts/default/`.
- Unit coverage in `tests/test_data_dir.py` (scoping + migration) and the cli suites; full
  suite (432) green.
