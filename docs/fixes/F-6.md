# F-6 — `execute()` books fills on submission with no order-status reconciliation

- **Fix ID:** F-6
- **Version:** 0.5.1
- **Date:** 2026-07-19
- **Status:** ✅ DONE (P-22, v0.5.1; 551 tests). Not live-verified offline — validate on a real venue
  with the capped [live smoke-test runbook](../live-smoke-test.md).
- **Related work:** surfaced during the backtest-simulator evaluation (P-17…P-21); the backtest
  replay loop (I-13) bypasses this path, so it is unaffected. This is a **live-execution** concern.

## Symptom

In live execution, a rebalance can record a fill that never happened. A maker limit order placed at
bid/ask ± offset typically **rests** (`status:'open'`, `filled:0`), but `ledger.jsonl` / `state.json`
/ `history.jsonl` are written as if the order fully filled at the limit price the moment it was
submitted. The next rebalance then computes drift from a fabricated post-trade balance, so state can
diverge from reality on the very first order — and drift may never actually converge.

## Root cause

`_fill()` ([execution_manager.py:209-220](../../src/ccbalancer/managers/execution_manager.py#L209-L220))
falls back to `order.limit_price` / `order.amount` when the ccxt `create_order` response lacks
`average` / `filled` — and because `0 or order.amount` evaluates to `order.amount` in Python, a
`filled:0` response still books the full amount. `_persist` writes the ledger/state/history on
**submission**, not on a confirmed fill. There is no order-status polling / reconciliation loop.

## Fix (approved design)

Two-phase booking: never book a fill on submission; book only from real exchange status, via a
`reconcile` step that also auto-runs at the start of the next `rebalance`. Fits DESIGN's
agent-driven/no-timer model (no blocking poll in `--execute`).

- **New per-account store** `stores/order_store.py` → `open_orders.json` (`config.data_dir`;
  `OPEN_ORDERS_FILENAME` in constants). One record per outstanding order, keyed by `client_order_id`:
  `order_id` (null until confirmed) · `symbol` · `side` · `amount` · `limit_price` ·
  `status` (`unconfirmed`|`open`|`partial`|`closed`|`canceled`) · `filled_booked` (cum qty already
  ledgered — partial-delta guard) · `placed_at`. Terminal records removed; atomic full-file rewrite.
- **New network read** `ExchangeStore.fetch_order(order_id, symbol)` (via `_request`, retryable) +
  a lookup-by-`clientOrderId` over `fetch_open_orders` to resolve `unconfirmed`/timed-out placements.
- **Rewrite `_place`:** write-ahead `order_store.put(unconfirmed)` **before** `create_order`; on
  success stamp `order_id`+status then reconcile that one order; on reject/insufficient → remove
  record + `FAILED`; on network/timeout → leave `unconfirmed` ("run reconcile"). **Delete** the
  fabricated `_fill`/`_persist` full-fill booking — placement writes only a `submitted`/`open` event.
- **New `ReconciliationManager`** (`reconcile(symbols, *, now)`): resolve id → `fetch_order` →
  `delta = filled - filled_booked`; if `delta>0` append `Fill(qty=delta, price=average, fee=…)`,
  record state/history, set `filled_booked=filled`; terminal → drop record. Idempotent (delta 0 →
  no write). `last_rebalance_at` set on **fill**, not placement (correct `TOO_SOON`; matches sim).
- **`execute()` auto-reconciles first**, before cancel-and-replace, so a partial is booked before the
  remainder is cancelled. Reconciler is a constructor-injected dep of `ExecutionManager`.
- **New `reconcile [--pair …]` command** — write category (venue+account; places no orders; **not**
  kill-switch-blocked); stable JSON + text summary; added to the taxonomy epilog.
- **Timeout ambiguity:** the deterministic `client_order_id` de-dupes re-placement and resolves a
  timed-out-but-landed order on the next reconcile — never lost or double-booked.

**Scope:** own phase, `fix/f-6-exec-reconciliation` branch, fix-only → **patch (v0.5.1)**. Tests all
offline via a `FakeExchangeStore.fetch_order` with programmable fill states (resting→nothing;
partial→full delta, no double-book; timeout→unconfirmed→resolved-by-coid; reject→removed;
auto-reconcile-before-cancel; idempotent re-run). **Limitation:** partial-fill fees best-effort
(incremental if the venue returns per-fill fee data, else 0). Validate live with the capped
[live smoke-test runbook](../live-smoke-test.md).

## Limitations

- **Partial-fill fees** are best-effort: the venue's cumulative order fee is booked once, on the
  terminal fill (intermediate partials book fee 0), so it is never double-counted.
- A placement that fails with a non-timeout `ExchangeError` (e.g. a bad symbol) leaves a write-ahead
  `unconfirmed` record that reconcile cannot resolve; it lingers harmlessly (books nothing) until
  manually cleared. A future prune pass could drop long-unresolvable records.
