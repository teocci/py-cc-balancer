# F-4 — `auth login`/private OKX calls crash inside ccxt `load_markets` on preopen instruments

- **Fix ID:** F-4
- **Version:** 0.1.3
- **Related phase:** Auth / Exchange store (F-3 follow-on)
- **Date:** 2026-07-16

## Symptom

`ccbalancer auth login --exchange okx …` (and any OKX call that loads markets)
crashes with an unhandled `TypeError`, exiting via the PyInstaller bundle's
"Failed to execute script" path:

```
TypeError: '<' not supported between instances of 'NoneType' and 'str'
  ccbalancer/stores/exchange.py, line 110, in fetch_balance
  ccxt/base/exchange.py, line 1556, in load_markets
  ccxt/base/exchange.py, line 3233, in set_markets
  ccxt/base/exchange.py, line 907, in keysort
```

It is **not** a credential problem (that was F-3): the crash happens before any
signed request, inside ccxt while parsing OKX's market list. It is also
**intermittent** — it fires only when OKX's live instrument list currently
contains a broken "preopen" placeholder, so the same command can succeed minutes
later.

## Root cause

A ccxt-side bug in our pinned `ccxt==4.4.94`. OKX occasionally returns "preopen"
placeholder instruments with an **empty `instId`**. `okx.parse_market` maps that
to `id = self.safe_string(market, 'instId')` → `None`. `set_markets` then stores
the market under a `None` key in `markets_by_id` — that path has **no** None
guard (unlike `index_by(values, 'symbol')`, which does skip `None`) — and
`keysort(self.markets_by_id)` (`exchange.py:3233`) raises when Python's `sorted()`
compares a `None` key against the string ids.

Reproduced deterministically offline (no network) by feeding a synthetic preopen
row (`instId=''`) plus a normal row through `okx.parse_markets` → `set_markets`
on 4.4.94: the preopen row parses to `id=None` and `set_markets` raises the exact
`TypeError`.

Upstream fixed this above our pin:

- **`v4.5.57`** (PR #28825, `fix(okx): loadMarkets`) — adds the guard
  `if instId == '': continue  # skip broken "preopen" placeholder instruments`
  in `fetch_markets_by_type`, so the broken row never reaches `parse_market`.
- Related OKX `parseMarket`/empty-market corrections at `v4.5.13` (#27149) and
  `v4.5.15` (#27216).

Our pin `4.4.94` predated all three.

## Fix

Bump the ccxt pin to the latest release, `4.5.65` (`pyproject.toml`). No
`ccbalancer` source change is needed — the defect and its fix are entirely inside
ccxt; `ExchangeStore` already wraps `load_markets` and translates ccxt errors.

On 4.5.65 the same offline repro no longer crashes (the preopen row is skipped /
carries a non-`None` id), and live `okx.load_markets()` returns 4058 markets cold
and on `reload=True` with no `None`/empty key present.

The bump was validated against the changelog-impact digest
(`docs/cctx/19-changelog-impact.md`), which had already reviewed the entire
`4.4.95…4.5.65` range and found no breaking change on our surface. After the bump
the digest was regenerated (delta now empty — we sit at ccxt's tip).

## Verification

- **Deterministic repro:** synthetic OKX preopen row → `set_markets` crashes on
  4.4.94, succeeds on 4.5.65.
- **Live OKX:** `okx().load_markets()` returns 4058 markets cold + `reload=True`;
  no `None`/empty market key present.
- **Unit suite:** full `pytest` green on 4.5.65 (402 tests) — guards the
  exchange-error mapping / retry boundary against the new version.
- **Changelog-doc action items** (all included at ≥ 4.5.57): `precision.amount`/
  `price` values **and** Python types byte-identical across 4.4.94↔4.5.65 for
  BTC/USDT + ETH/USDT on bybit/binance/okx (v4.5.48 precision refactor, v4.5.65
  parseJson); `load_markets(reload=True)` still refetches.
- **Portable bundle:** rebuilt with `packaging/ccbalancer.spec`; `_internal/`
  now collects the new ccxt C-extension deps (`coincurve`, `cryptography`,
  `orjson`, `winloop`); warn file shows only harmless optional misses. A live
  signed private call (`auth status`, active bybit profile → `credentials:
  valid`) succeeds in the frozen bundle, proving ccxt 4.5.65 + orjson + HMAC
  signing all work when packaged.
- **Residual verify-on-live item** (needs testnet creds, not run here): place a
  tagged OKX testnet order and confirm `execution_manager.is_ours()` still
  matches it (OKX broker-code change, v4.5.2 #26689) before trading OKX live —
  tracked in `docs/cctx/19-changelog-impact.md`.
