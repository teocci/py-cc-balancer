# I-8 — Per-account data isolation + stable identity

- **Improvement ID:** I-8
- **Version:** 0.2.0
- **Date:** 2026-07-17
- **Status:** ✅ DONE (432 tests; live-verified).
- **Related work:** delivers the [F-5](../fixes/F-5.md) correctness fix; siblings [I-5](I-5.md), [I-6](I-6.md), [I-7](I-7.md).

## Objective

Give each account its own data book keyed by an immutable local id, so switching accounts
never mixes one account's balances, state, or P&L with another's. This is the improvement
that closes bug [F-5](../fixes/F-5.md) (a shared global book silently corrupting
cross-account P&L).

## Approach

Each account's book lives under `accounts/<id>/`, keyed by a **stable, immutable local id**
(not the mutable slug, not a creds hash — both would strand a book on rename / key rotation):

- New `AppConfig.data_dir = app_dir / 'accounts' / <account.id>` (or `accounts/default/` for
  the no-account env-credential path). The six book files (`portfolio.json`, `state.json`,
  `history.jsonl`, `ledger.jsonl`, `decision_log.jsonl`, `flags.json`) route through
  `data_dir`; global/public files (`config.toml`, `indicators.toml`, `auth.json`, `.env`,
  `STOP`, `ohlcv/`) stay on `app_dir`.
- The `id` is minted once (`secrets.token_hex(6)`) at first save and preserved across
  `auth rename` ([I-7](I-7.md)) and in-place credential rotation (`auth login` of the same
  name), so the book is never stranded.
- The **keyring stays keyed by account name** (not id) — a deliberate deviation from the
  original plan to avoid a risky one-time migration of the OS credential store. `auth rename`
  moves the keyring entry to the new name (re-persist under the new name, then `forget` the
  old); the data dir is untouched because it is keyed by the stable id.
- A best-effort exchange **`account_ref`** (hashed exchange account id, captured online at
  login via `ExchangeStore.account_ref()`) **guards credential rotation**: re-logging into an
  existing account with a key that resolves to a *different* exchange account is refused
  (`--force` overrides), so a rotated key can never silently re-point an account's book at a
  different real account.
- One-time guarded migration (`_migrate_legacy_book` + `AuthStore.ensure_ids`) assigns
  existing root-level books to the account **resolved for the first invocation** (the same
  `data_dir` that command reads, so a `--account`/`CCB_ACCOUNT` selection is honored rather
  than silently overridden by the active pointer). The move is per-file and idempotent
  (atomic `Path.replace`; a file whose scoped target already exists is left in place, so one
  pre-scoped book can't strand the rest). Ids are minted for pre-0.2.0 accounts. Prior
  cross-account mixing already in `ledger.jsonl` predates the fix and cannot be retroactively
  separated.

**Scope note:** automatic reattach after a *full* `auth logout` + re-login is **not**
implemented — logout removes the stored `account_ref`, so the returning account is minted a
fresh id (a new empty book). The old book directory persists on disk (recoverable), so no
data is lost. `account_ref` today powers the rotation guard; logout/re-login reattach would
need a tombstone and is left as a future enhancement.

## Verification

- **Live isolation (F-5):** two real accounts (bybit, okx) each hold their own book —
  `pair add` under one is invisible to the other; on-disk `accounts/<id-a>/` and
  `accounts/<id-b>/` are distinct.
- **Live `account_ref`:** `ExchangeStore.account_ref()` returns a stable hashed id for the
  real bybit account (matches the standalone tier-2 `/v5/user/query-api` probe).
- **Rename:** `auth rename` preserves the id and the book (BTC/USDT intact under the new
  name); the active pointer follows.
- **Rotation guard:** same-ref rotation keeps the id and updates the key; a different-ref
  rotation is refused (exit 2) unless `--force`.
- **Migration:** legacy root books move once into the active account's dir (idempotent;
  no duplication); the env path lands in `accounts/default/`.
- Unit coverage in `test_data_dir.py`/`test_account_ref.py`/`test_cli_auth.py`; full suite
  (432) green.
