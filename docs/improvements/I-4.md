# I-4 — Multi-machine state sync

- **Improvement ID:** I-4
- **Version:** backlog (unscheduled)
- **Status:** 📋 BACKLOG

## Objective

Let the tool run from more than one machine against the same account without the local
`state.json` drifting out of sync with reality.

## Approach

- Reconcile `state.json` (last rebalance per pair, tagged order state) from the exchange's
  own order history rather than trusting only the local file.
- On startup or on demand, fetch open/recent orders for the account's pairs and rebuild the
  local view, so a second machine picks up what the first one did.
- Keep the append-only logs (`history.jsonl`, `ledger.jsonl`) as the local record; the sync
  targets the mutable `state.json`.
