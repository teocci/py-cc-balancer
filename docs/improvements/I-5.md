# I-5 — Command-scoped CLI flags

- **Improvement ID:** I-5
- **Version:** 0.2.0
- **Date:** 2026-07-17
- **Status:** ✅ DONE (432 tests).
- **Related work:** siblings [I-6](I-6.md), [I-7](I-7.md), [I-8](I-8.md).

## Objective

Stop global flags from leaking onto subcommands that do not use them, so each
subcommand's `--help` shows only the flags that actually apply to it.

## Approach

- Split the monolithic `_common_flags()` into composable argparse parents so flags attach
  only to the commands that consume them.
- Result: `--profile`/`--pair` no longer appear on `auth login`, `pair`, `config`,
  `analyze`, or `indicator` help output — only where they are meaningful.
- Behavior of the flags themselves is unchanged; this is a wiring/organization change to
  the CLI parser in `cli.py`.

## Files changed

| File | Change |
|---|---|
| `src/ccbalancer/cli.py` | Split `_common_flags()` into `_base_flags`/`_account_flag`/`_venue_override_flags`/`_pair_flags`; compose per-command parents in `build_parser` and each `_add_*`; `_load_config` reads `--config/--exchange/--testnet/--account` via `getattr` so absent parents fall through to env/TOML/default |
| `tests/test_cli_surface.py` | New — parametrized per-command help-flag assertions |

## Verification

- `auth login --help`, `pair add --help`, `analyze --help`, `config init --help` show only
  applicable flags — no stray `--profile`/`--pair`; `auth status --help` keeps `--account`
  only; `status --help` keeps the full set.
- `tests/test_cli_surface.py::test_command_flag_surface` (parametrized) and the full suite
  (432) pass.
