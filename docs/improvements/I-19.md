# I-19 — Paper account: auth/config integration, funding, reset

- **Improvement ID:** I-19
- **Version:** 0.6.0
- **Date:** 2026-07-19

- **Related work:** Wires the [[I-18]] `PaperExchangeStore` into the account/auth/config plumbing

## Objective

Wire the paper backend into the account/auth/config plumbing so **every live command runs unchanged**
against a paper account. A paper account keeps a real underlying exchange id (for public data) plus a
`paper` flag — no fake `'paper'` venue, so the `SUPPORTED_EXCHANGES`/`_QUIRKS` invariant is untouched.
`auth login --paper` creates and funds it; `paper reset` re-seeds it.

## Approach

- `Account` gains `paper: bool`; persisted by both auth backends (file inline + keyring metadata) and
  read back in `_account_from_meta`. `AppConfig` gains `paper` (resolved from the account);
  `require_credentials` returns early for paper accounts (nothing to verify), and `masked_summary`
  surfaces it.
- `auth login --paper` (name defaults to `paper`, `--account` overrides): skips credential collection
  and live verification, mints the stable id, and seeds the all-stable book (`--paper-capital`,
  `--paper-quote`, defaults from constants). The real `--exchange` still picks the public data venue.
- Store routing: `_exchange_store(config)` and `_account_exchange_store(account)` return a
  `PaperExchangeStore` when the account is paper, via a shared `_paper_exchange_store(data_exchange,
  testnet, data_dir)` builder. `config.account_data_dir` (newly public) bridges the account's data dir
  into the account-only seam.
- New `paper reset` command re-seeds the book to a fresh balance (re-login keeps the same book, so a
  reset path is needed); errors on a non-paper account.
- Docs: `docs/paper-account.md` runbook + DESIGN.md (Account key-decision, file layout, taxonomy,
  backtest-vs-paper distinction).
