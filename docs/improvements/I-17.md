# I-17 — simulation run --targets: external target schedule

- **Improvement ID:** I-17
- **Version:** 0.6.0
- **Date:** 2026-07-19
- **Status:** ✅ DONE (589 tests; live-verified).
- **Related work:** Builds on the I-13/I-15 simulation replay engine; sibling of [[I-18]]/[[I-19]] in the same plan

## Objective

Let `simulation run` replay a **per-decision target schedule** (a forward-filled step function) instead
of the pair's single static `target_volatile_pct`, so an external brain can backtest a *moving*
volatile/stable ratio while the CLI keeps applying its own band / min-cost / fee mechanics at each bar.
Purely additive — with no `--targets` flag the backtest behaves exactly as before.

## Approach

- New `stores/target_schedule.py`: `load_target_schedule(path)` parses a JSONL file
  (`{"date","target_volatile_pct"}` per line) into a validated, ascending `TargetSchedule` — targets in
  `[0,100]`, dates strictly increasing — exposing a bisect `target_at(open_ms)` lookup, a
  `covers_start(start_ms)` check, and a stable `digest()`.
- The pure `RebalanceManager.decide` is **unchanged**. In `replay()` a per-bar `PairConfig` is derived
  via `dataclasses.replace(pair, target_volatile_pct=t, target_stable_pct=100-t)` when a schedule step
  covers the bar (else the configured target stands), and passed to both `decide` and the snapshot.
- Determinism/provenance: the schedule `digest()` is folded into `_run_id` (a different schedule → a
  distinct id; a re-run is byte-identical) and recorded in `run.json` (`target_schedule_digest`/`_steps`).
- CLI: `--targets PATH` on `simulation run`; the handler loads+validates the schedule and warns (stderr)
  when no step is at/before `--start`.

## Verification

`.venv/Scripts/python -m pytest tests/ -v` (all green). CLI e2e drives the full parse → load → replay →
run_id → run.json → render path with a real store; a scheduled run yields a distinct `run_id` and a
different fill count than the static run, and an out-of-range schedule exits with a config error.
