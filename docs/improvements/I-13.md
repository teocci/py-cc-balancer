# I-13 — Bar-crosses-limit replay engine — virtual balance, resting book, sim ledger, `simulation run`

- **Improvement ID:** I-13
- **Version:** 0.4.0
- **Date:** 2026-07-18
- **Status:** ✅ DONE (506 tests; live-verified).
- **Related work:** P-17, P-19

## Objective

Replay candles from --start; decide on closed candles only (no look-ahead); resolve fills on the next candle whose range crosses the limit (BUY next_low<=limit / SELL next_high>=limit), else rest/re-quote; enforce precision + min-notional; mutate a virtual balance seeded from --capital; write simulated Fills to an isolated sim ledger. Expose `simulation run`. A run is deterministic (same inputs -> byte-identical ledger).

## Approach

- Dedicated replay loop (NOT `ExecutionManager.execute`, whose synchronous book-on-submit can't
  express next-bar resting fills). The decision timeframe (default `1d` for the MVP) drives cadence.
- At each decision point, build a `PairSnapshot` from the current closed candle and call the pure
  `RebalanceManager.decide` (reused unchanged). Proposed orders enter a resting book.
- **Bar-crosses-limit fill model:** on each subsequent candle, a BUY fills when `next_low <= limit`,
  a SELL when `next_high >= limit`; otherwise it rests and re-quotes at the next decision (mirroring
  live cancel-and-replace). Enforce precision + min-notional from market metadata so sub-minimum legs
  are rejected exactly as live (the "never converges" failure stays visible).
- Virtual balance seeded from `--capital` (default all-stable; first decision establishes target);
  filled orders emit `Fill`s and mutate it. Sim ledger written under `simulation/runs/{run_id}/`.
- `simulation run` command (compute only). A run is **deterministic** — same inputs → byte-identical
  ledger.
- Tests (on the daily sample): no look-ahead (a fill never resolves on the decision bar); crossing
  next-bar fills, non-crossing rests; sub-min-notional → `OrderRejectedError`; balance mutates only
  on fills; determinism.
